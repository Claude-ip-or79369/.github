<p>按并发计费听起来很省钱，但省不省要看你的用量曲线长什么样。一个常年在线的十个号，按并发买和按条买的总价可能只差两成；而一个每天只跑两小时批量的团队，按并发能省掉一大半。这篇给一份可以直接照着走的决策清单：先判断形态，再问五个必答题，然后验收、约定异常跟进，最后列出三种不该选按并发的情况。整篇按「决策—下单—验收—运维」的顺序排，方便逐项打勾。</p>

<h2>一、第一步：先判断你的用量曲线属于哪种形态</h2>
<p>计费方式没有优劣，只有匹配与否。判断依据是同时在线数与在线时长的组合。</p>
<h3>三个问题定形态</h3>
<p>同一时刻最多有几个任务在跑？这些任务一天里集中在线几小时？深夜和周末是否完全空闲？三个答案组合起来就是一条曲线。曲线平直且高位，按条或包月更划算；曲线尖峰明显、低谷接近零，按并发更省。</p>
<h3>把并发数算准，不要估</h3>
<p>并发指的是同一时刻活跃的连接数，不是账号总数。十个号里通常只有三到五个同时活跃。做法是连续三天在业务高峰用 <code>netstat -an | grep ESTABLISHED | wc -l</code> 或监控面板采样，取 95 分位值作为并发上限，按上限买而不是按账号数买。</p>
<p>余量方面，按实测值加两成下单就够：按 95 分位加两成余量下单，比按峰值买省得多，也不至于天天顶格。顶格运行的线路，失败率会明显上来，省下的钱要用返工去还。</p>

<h2>二、第二步：五个必答题，问不清就别下单</h2>
<p>这五个问题决定的是「买贵了」还是「买了不能用」，比价格重要得多。</p>
<h3>并发怎么计量、超了怎么办</h3>
<p>问清并发是按「同时活跃连接」还是「同时在线账号」计；超出的瞬间是排队、限速还是直接拒绝；是否有突发额度。三者的体验差别很大，排队最温和，直接拒绝会打断正在跑的会话。</p>
<h3>开通要多快、说明给到什么程度</h3>
<p>「开通即用」要落到具体：付款后多久能拿到地址与鉴权信息，是分钟级还是当天；操作说明是几行文字还是含示例的完整文档，有没有针对你所用客户端的配置样例。文档质量直接决定你花多久能跑通。</p>
<h3>出口异常谁跟进、多久响应</h3>
<p>要问到具体的人和渠道：是工单、群还是专属对接；工作时段外怎么处理；换新地址的时效是几小时还是隔天。没有明确响应时效的「专人跟进」，在真出事时等于没有。</p>

<h2>三、第三步：开通当天的验收，别等出问题才查</h2>
<img src="/tp.png" alt="Claude住宅IP按并发开通后核对出口与上限">
<p>验收做得好，后面省一半沟通。半小时能做完，建议当天做。</p>
<h3>四项基础验收</h3>
<p>一是出口地址类型，访问 <code>https://ipinfo.io/json</code> 确认 <code>type</code> 为 residential、<code>org</code> 为当地运营商；二是地理一致性，城市与账号资料里的地区能对上；三是并发实测，按购买值的八成压测十分钟，看失败率是否低于百分之一；四是鉴权方式，确认账号密码或白名单哪种生效，IP 白名单要提前报备。</p>
<h3>把基线数据存下来</h3>
<p>记录开通当天的延迟、下载速率、失败率各三次采样，存成一张对照表。后面任何一次「感觉变慢」，都能拿这组数对比，避免凭感觉换资源。</p>

<h2>四、第四步：出口异常的跟进流程要提前约定</h2>
<p>异常一定会发生，区别在于发生时你是否知道该找谁、该给什么信息。</p>
<h3>报障时该带的三样东西</h3>
<p>出现异常的时间点（精确到分钟）、当时的出口 IP 与检测页截图、以及失败请求的返回码。三样齐了，对方能直接定位；只发一句「连不上」，来回沟通就要几轮。</p>
<h3>换新的判定标准</h3>
<p>同一地址 24 小时内三次以上失败、或地址类型从 residential 变为 hosting、或同段多个账号同时异常，满足任一条就该申请换。不要等到账号被要求验证才动，那时损失已经发生。</p>
<p>最后把时效写进约定：工作时段内几小时响应、非工作时段是否有人、换新的最长时间，这三条最好在下单前用文字确认。口头承诺在扯皮时没有约束力，一条聊天记录就够。</p>

<h2>五、第五步：三种情况不该选按并发</h2>
<p>清单走到这里，如果命中下面任意一条，建议直接换计费方式。</p>
<h3>常年在线、并发平稳</h3>
<p>七个号全天挂着，按并发买的总价往往高于按条包月。这类用法波动小，包月更可预测。</p>
<h3>并发需求极低但连接要长</h3>
<p>只要一条长连接，按并发的最小起售单位可能就浪费了大半。这种更适合按端口或按小时的形态。</p>
<h3>账号数少且集中在白天</h3>
<p>三五个号、只在工作时间用，按并发能省，但省的绝对金额不大，反而多了一层计费沟通成本。规模太小时，简单可预期的方案更省心。</p>

<h2>常见问答</h2>
<h3>并发买了十个，是不是能同时开十个号？</h3>
<p>答：不一定。并发指同时活跃的连接数，一个号可能占用多个连接（页面、接口、心跳），十个并发未必撑得住十个号同时操作。建议按实测的连接数换算，而不是按账号数直接对应。</p>
<h3>开通后发现并发不够，能临时加吗？</h3>
<p>答：多数服务商支持按天或按月追加，但要问清是否需要重启线路、追加部分如何计费。若追加必须换地址，就等于一次跳变，最好一次性买够余量。</p>
<h3>出口异常找谁，多久能有结果？</h3>
<p>答：下单前就该确认渠道与时效。实操上把响应时间写进聊天记录，报障时附上时间点、出口 IP 和返回码，能显著缩短处理轮次。</p>
<h3>按并发比按条便宜多少？</h3>
<p>答：取决于曲线形状，没有统一答案。尖峰型用量常见能省三到五成，平稳型反而更贵。价格区间因地区与服务商差异较大，仅供参考，建议用自己一周的真实采样数据去算。</p>
